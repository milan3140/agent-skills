# UIUX Design Check

**觸發條件**:設計/重設計/檢核任何 UI、討論介面美學、產出設計規格。做這些事**先讀本 skill 再動手**,不要憑感覺直接畫。

---

## 第 0 步:分流

| 情境 | 走哪條 |
|---|---|
| 從零設計 / 全面檢核 | 完整流程 §1–§6 |
| 既有系統增量加介面 | §1 檢核 + §4 原型 + §5 規格(§2 對標可縮小到 2 個範例) |
| 只要 design token 起手包 | 直接看 §5.1 |

情境模糊 → 走完整流程。

---

## §1 檢核本設計

逐面向檢核,**寫出因果**(這裡怎麼做 → 為了什麼設計目的 → 如何達成),不是打勾:

| 面向 | 要回答的問題 |
|---|---|
| 資訊架構 | 使用者的管理單位是什麼?分組軸選對了嗎?層級是否多過內容(鷹架 > 內容 = 看不懂) |
| 視覺層級 | 字級/粗細/留白/色階,四種訊號是否指向同一個層級結論? |
| 顏色語意 | 顏色編碼的是**狀態/急迫度**還是**結構**?(結構應交給留白與分隔線) |
| 密度與節奏 | 掃視時眼睛落點在哪?每行資訊量是否超過一次可讀範圍? |
| 互動可見性 | 可點的看起來可點嗎?>2 秒的操作有沒有事件驅動的進度回饋? |
| 動效 | 入場/離場都有嗎?是否只在「本次觸發的元素」上播? |
| 空狀態/錯誤 | 沒資料、載入失敗、權限不足各長什麼樣?有沒有下一步? |
| 無障礙 | 對比度、鍵盤操作、focus 可見、字級可放大 |
| 一致性 | 同一種東西在不同頁面長得一樣嗎?數值是否來自單一 token 來源? |

---

## §2 上網對標(**強制,不可略過**)

**規則:沒有找過真實範例就不准開始畫。**

1. 到 **AWWWARDS / Dribbble / Mobbin / 競品實際產品**,找**至少 5 個**同類型介面(同樣的資訊型態與使用情境,不必同產業)
2. 每個範例過一遍 §1 Checklist,記下它「怎麼解你正在解的那個問題」
3. **產出 5 條 Best Practice**,每條格式固定:

```
[做法] + [在哪個產品/頁面看到] + [它解決什麼問題] + [在我們的場景怎麼套用]
```

只寫「要有留白」這種通則**不算數**——沒有出處、沒有套用方式的條目視為未完成。

---

## §3 視覺效果的最佳實作研究(**強制**)

設計若包含特定視覺效果(玻璃質感、模糊、光暈、陰影、漸層、液態變形、骨架屏…),
**一定要先查出「業界把這個效果做到最好的是誰、他怎麼做」**,再開始實作。

| 效果 | 去看誰 | 要抄的重點 |
|---|---|---|
| **玻璃質感** | **iOS Liquid Glass / macOS 材質層** | 一個介面**只有一層玻璃**;內容是材質的一部分(靠透明度與 vibrancy 表現),不是玻璃上再疊卡片;高光來自光源方向而非描邊;景深由模糊半徑而非陰影堆疊 |
| 陰影/浮起 | Material 3 elevation | 陰影表達的是**距離**不是裝飾;同層級元素陰影必須一致 |
| 動效曲線 | iOS spring / Material motion | 進場快、出場慢;一個產品只用一組 easing |
| 資料視覺化 | FT / Economist / Observable | 先選圖表型態再選顏色;顏色編碼量值不編碼身分 |
| 骨架屏 | Facebook / LinkedIn | 骨架形狀對應真實內容版位,不是灰色方塊 |
| 深色模式 | Apple HIG dark | 不是把顏色反相;是重新選一組在暗背景仍有層次的色 |

**產出:效果實作筆記**——該效果的物理直覺、對方用的具體參數(層數、模糊半徑、透明度、光源角度、時長),我們要抄哪幾點、放棄哪幾點。

## §4 ASCII 原型提案(**強制閘門**)

給 **2~4 個候選**,每個候選代表**不同的使用者心智模型 / 使用邏輯**,不是同一版面的微調:

```
候選 A —— 心智模型:「我照時間順序處理事情」
┌──────────────────────────────┐
│ 09:00 ● 會議 A                │   ← 時間軸為骨架
│ 10:30 ○ 待辦 B  ‧ 等你回覆     │
└──────────────────────────────┘

候選 B —— 心智模型:「我按專案分責任」
┌──────────────────────────────┐
│ 專案 X          3 件 ‧ 1 要回 │   ← 管理單位為骨架
│   └ 待辦 B      等你回覆       │
└──────────────────────────────┘
```

每個候選必須標:
- **心智模型一句話**(使用者腦中怎麼想這件事)
- **真實比例與尺寸**(等寬字元對齊、標關鍵尺寸)
- **真實內容**(真文案,禁 Lorem/假字)
- **互動 affordance**(哪裡可點、點了會怎樣)
- **這個模型什麼情況會壞掉**(誠實寫出弱點)

**挑定前不寫規格、不動工。**

## §5 產出設計規格

挑定的 ASCII 圖直接貼進規格當版面藍圖,再補:

### 5.1 Design token(單一來源,禁止硬編碼)

```
色彩  語意色(狀態/急迫度)+ 中性階(帶品牌色相的灰)
字級  5 級(例 10/11/12/13/16),不再新增級距
間距  4px grid;縮排階梯明列
圓角  3 級
動效  單一 easing + 3 種時長(hover / 狀態 / 面板)
```

**token 必須能被設定檔注入**(如 `theme.json`),不要寫死在 CSS/元件內——換皮、換品牌、做多主題都靠這層。

### 5.2 元件規格
每個元件:結構、狀態(default/hover/active/disabled/loading/empty/error)、尺寸、間距來源、可及性。

### 5.3 驗收條件
用「使用者眼睛看得到的東西」描述,並附**可量測檢查**(例:動畫要量 `getComputedStyle` 的過渡序列,不能只看截圖;閃動要量 `getAnimations()` 的 running 數)。

---

## §6 存放

規格文件存到**當前工作專案的設計資料夾**(跟著專案走,不放工具庫)。

---

## 絕對鐵則(違反 = 重做)

- 美學標竿:Linear / Stripe / Notion / Vercel;原則基礎:Apple HIG + Material。
- Icon 一律 SVG(Lucide 等),**嚴禁 Emoji 當 icon**。
- **嚴禁卡片式堆疊**(圓角填色容器 + 陰影浮起 + 內縮 margin);改用分隔線、縮排、留白、全寬色帶。
- 不「修補」,要建立**統一設計邏輯系統**;所有數值出自 token。
- **顏色只編碼急迫度/狀態,永不編碼結構**。
- 入場動畫只綁本次觸發的元素,否則重繪會全體重播 = 整片閃動。
- **被退 ≥2 次立刻停止修補**,回 §1 重跑流程,產出原型讓對方挑。
- 收尾必跑 A–G 審計:視覺減法 / 間距節奏 / 光學校正 / 色彩精修 / 構圖 / 元件 polish / 一致性。

## 常見失敗模式(實戰累積)

| 症狀 | 根因 | 解 |
|---|---|---|
| 「很亂、看不懂」 | 鷹架(標題層)比內容多 | 算 內容行/鷹架行 比,<2 就砍層;低層維度降為行內標籤 |
| 「很醜、像插了幾塊東西」 | 卡片式堆疊、各元素獨立材質 | 一個介面一層材質;全寬色帶取代內縮卡片 |
| 「這裡髒髒的」 | radial 漸層放在高度不定的容器,中段留殘影 | 改 linear 左緣暈或直接平坦 |
| 「標題跟內容像兩塊」 | 標題有自己的底色 | 標題與內容共用同一塊底色 |
| 「點開會閃」 | 動畫寫死在元素上,重繪全體重播 | 只給本次觸發的元素加 `.opening` |
| 「不知道這是什麼」 | UI 出現內部代碼/術語 | UI 只用使用者語言,代碼放展開層 |
| 「每次都要重講」 | 沒有 token 與規格文件 | §5 產出並存進專案 |
